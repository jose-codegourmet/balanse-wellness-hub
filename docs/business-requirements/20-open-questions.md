# 20 — Open Questions

The core booking model is defined, but these business decisions still need confirmation.

## High priority

### 1. Cancellation eligibility window

Can a customer request cancellation:

- at any time before class,
- only before a defined cutoff,
- even after class for admin review?

Does timing affect refund eligibility?

### 2. Reschedule policy

Need answers for:

- reschedule cutoff,
- number of allowed reschedules,
- same class only vs any class,
- how price differences work,
- whether full target sessions can accept reschedule requests through waitlist.

### 3. Required profile fields

What exact customer information does Coach Rex require?

Examples:

- full name,
- phone,
- date of birth,
- emergency contact,
- health-related declarations.

Do not add sensitive fields unless the business genuinely requires them.

### 4. Actual waiver and policy documents

Coach Rex must provide:

- waiver text,
- gym policies,
- cancellation/refund policy if one exists,
- participation rules.

### 5. Waiver re-acceptance rule

Should users accept:

- on every booking,
- only when version changes,
- once per fixed period?

## Medium priority

### 6. Session cancellation communication

What communication should customers receive when Rex cancels a class?

- in-app only,
- email,
- both?

### 7. Admin rejection reasons

Should rejection reasons be:

- free text,
- predefined,
- both?

### 8. Payment-proof requirements

Do they need:

- screenshot only,
- transaction/reference number,
- amount,
- payer name?

### 9. Confirmation/reference format

Does Balanse want:

- human-readable booking reference,
- QR code for confirmed booking,
- just an in-app status?

### 10. Session completion

Does the app need a formal `COMPLETED` status after class, or is `CHECKED_IN` enough for MVP?

## Lower priority / future

- memberships,
- packages,
- automated payments,
- recurring schedules,
- coach portal,
- notification automation,
- multiple branches.
