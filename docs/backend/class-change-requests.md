# Coach class change requests (WIRE-E20, #374)

`ClassChangeRequest` stores a coach's request to move a future session, assign a substitute, or cancel it. The record snapshots the class name, original window, and coach roster so resolved requests remain readable after the session changes. The database permits one `PENDING` request per session through a partial unique index. The request and action routes are listed in `packages/db/contracts/routes.ts`.

The API derives the staff and coach identities from the signed-in actor. An assigned coach with `schedule.read.own` may create and withdraw their own request. Staff with `schedule.update` or `schedule.cancel` may read the review queue; approval and denial require the permission for that request kind. Self-review is forbidden. Approval changes the session and resolves the request in one transaction. Rescheduling moves the session's window, so existing bookings follow their session. Substitution replaces the requesting coach's `session_coaches` assignment with a new rate snapshot. Cancellation calls the same transaction helper as direct session cancellation, including event cancellation. A session audit record lists active booking IDs for manual customer contact; no automatic message is sent.

The table grants only `SELECT` to authenticated Data API callers. Its RLS read policy permits reviewers or the requesting coach; there are no direct client write grants. The status-change trigger writes an `audit_events` row in the same transaction. API writes also check permissions and ownership before mutation.

The additive migration is staged in both `supabase/migrations/20261013022042_wire_e20_class_changes.sql` and `packages/db/prisma/migrations/20261013022042_wire_e20_class_changes/migration.sql`.
